# HarborGrid · 港口集装箱堆场作业协同与闸口调度系统

React + Vite + TypeScript 前端，Node.js + Express + TypeScript 服务端。面向中型集装箱码头，把船期、箱务、堆场区块、闸口预约、设备作业和异常闭环放在同一套作业控制台中。

## 启动

```bash
npm install
npm run dev
```

前端默认 Vite 端口 5178，API 默认 `http://localhost:4107`。

## 业务能力

- 船舶航次、泊位窗口、计划/已完成翻箱和延误风险
- 箱号、尺寸、冷藏温度、危险品级别、海关状态、进出口/中转流向
- 堆场区块容量、堆存热度、冷藏插座、危险品隔离和设备可达性
- 闸口预约时隙、车道、OCR/称重/封志校验状态与同车冲突检测
- 岸桥、场桥、集卡、正面吊设备池和约束感知任务队列
- 自动堆位推荐、冷藏/危险品约束、海关查验阻塞、任务指派审计
- 铁路交接批次：从箱务/铁路预约/场内任务建批，集结扫描加箱、撤出、封批、发运、部分/重复到站确认、海关查验拦截与可审计解封（查验/箱号不符/窗口变更）、重新封批与批次取消；批次状态与箱子流向、海关状态、铁路闸口车道和场内任务实时联动
- React 控制台支持船期驾驶舱、闸口操作、铁路批次交接、堆场热区与设备任务操作

当前使用内存种子数据，领域服务通过 REST API 暴露，后续可接入 TOS、OCR、称重、RTG 遥测、预约配额、铁路 95306 报文和优化求解器。

## 铁路交接批次状态机

```
draft 集结中 ──封批（校验流向/海关/rail 车道/场内任务）──▶ sealed 已封批
sealed ──铁路闸口全部签到后放行──▶ in-transit ──全部箱到站确认──▶ arrived
sealed/in-transit ──查验|箱号不符|窗口变更（留审计）──▶ 解封态(箱单可改) ──重新封批──▶ sealed/in-transit
draft/sealed(解封后) ──取消（留原因，箱回集结区）──▶ cancelled
```

- 封批后箱单冻结：加箱/撤箱/改窗口一律拒绝，必须先按三种合法原因解封，解封-重新封批全程写入审计链。
- 海关查验拦截自动解封并把箱置为 `intercepted`，放行回箱单（需海关已放行）或查验后撤出；在途批次撤出后自动重封，剩余箱继续到站。
- 到站扫描：重复扫描、部分到站、外批箱号不符都有明确结果；撤出的箱不计入应到站。
- `GET /api/rail/batches` 视图直接给出每个批次的 `missingYard`（场内缺箱+阻塞原因）和 `missingStation`（在途缺箱）。
